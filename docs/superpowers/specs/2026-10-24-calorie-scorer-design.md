# 热量打分器（Calorie Scorer）设计稿

日期：2026-10-24
状态：待用户复核

## 1. 产品概述

上传一张菜品照片，AI 识别菜品并估算热量与营养，用多巴胺配色呈现「热量 / 营养 / 趣味」三维评分，结果可修正、可分享，并计入每日热量总览。

一句话：**拍一张菜，几分？**

全程显式提示：**AI 估算结果仅供参考，可能不准，可手动修正。**

## 2. 范围

- 单菜模式：一张图 = 一道菜，输出该菜分数卡。
- 整餐模式：一张图 = 多道菜，逐道识别后加权汇总为一餐总分。
- 本地历史记录、每日热量总览、分数卡导出分享。
- 手动修正：增删菜品、修改克数/热量后自动重算。

不做：账号体系、云端存储、社交互动、营养医学建议。

## 3. 技术架构

```
浏览器页面 (public/index.html + app.js + style.css)
        │  POST /api/analyze  { imageBase64, mode }
        ▼
Node 代理 (server.js, Express)
        │  转发 + Authorization: Bearer <key>
        ▼
deepseek-flash 视觉接口  base_url = https://api.deepseek.com
        │  OpenAI 兼容 /chat/completions，图片以 image_url + base64 传入
        ▼
页面解析 → 打分 → 渲染
```

- 选型：方案 B（前端 + 本地代理）。
- Key 仅在服务端 `.env`，前端不出现。
- 代理同时解决 CORS 与 Key 暴露问题。

### 3.1 配置项（.env）

```
DEEPSEEK_API_KEY=        # 后续由用户提供
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
PORT=3000
```

### 3.2 已知风险

- DeepSeek 官方接口是否支持图片输入需在实现阶段用真实 Key 实测验证。
- 若不支持，代理层返回明确错误，页面提示「当前模型不支持图片识别」，并保留切换视觉模型的单点配置（只改 `.env`）。

## 4. 页面结构（单页三视图）

| 视图 | 内容 |
|---|---|
| 首页 | 上传/拖拽/拍照入口、单菜·整餐切换、示例图 |
| 结果页 | 多巴胺分数卡（总分 + 三项分值 + 识别明细 + 克数/热量）、修正、分享、重拍 |
| 今日总览 | 每日热量进度条、记录列表、目标值设置、清空记录 |

## 5. 打分模型

声明：以下为启发式娱乐规则，非医学/营养建议，权重集中在一处可配置。

| 维度 | 规则 | 权重 |
|---|---|---|
| 热量分 | 单人单菜 200–600 kcal 视为舒适区得高分，过高/过低递减 | 0.40 |
| 营养分 | 蛋白/脂肪/碳水比例均衡度 + 蔬菜占比 | 0.35 |
| 趣味分 | AI 主观评估：下饭指数 / 罪恶感 / 减脂友好度 | 0.25 |

- 综合分 = 热量×0.4 + 营养×0.35 + 趣味×0.25
- 等级映射：85+「快乐星球」；70–84「还不错」；50–69「中规中矩」；<50「罪恶深重」
- 整餐模式：逐道打分后按热量占比加权汇总。
- 每日目标默认 1800 kcal，可修改。

## 6. 多巴胺视觉规范

- 主色板：粉 `#FF3D7F`、橙 `#FF8A00`、黄 `#FFD400`、青绿 `#00E0A4`、紫 `#7C5CFF`、亮蓝 `#0FF0FC`
- 用色逻辑：分数越高越暖亮；越低越偏粉紫。
- 视觉特征：大圆角色块、粗描边卡片、超大数字 + 表情、撞色分段进度条、轻量弹跳动效。
- 分享卡：固定 3:4 画幅，html2canvas 导出 PNG。

## 7. 数据结构（localStorage）

```
meals: {
  id, timestamp, mode, thumbnail,
  items: [{ name, grams, kcal, confidence }],
  scores: { calorie, nutrition, fun, total },
  level
}[]
dailyGoal: number
```

## 8. 错误与边界

- AI 返回非法 JSON → 容错解析，失败提示并允许重试。
- 置信度低 → 标注「不确定」，引导手动修正。
- 图片过大 → 前端压缩至 ≤1024px 后上传。
- 未配置 Key / 网络失败 → 页面明示原因，不静默失败。

## 9. 验收标准

1. 上传单菜图，得到三维分数与综合分，颜色随分数变化。
2. 整餐模式多道菜逐条列出并汇总总分。
3. 数值可手动修正并实时重算。
4. 记录进入今日总览，热量进度条同步增长。
5. 分享卡可导出 PNG。
6. Key 不出现在前端任何代码或请求中。
